# Core Release Guide

The current published OrbitFabric Core product is [v1.4.0](v1.4.0.md).

The release notes are organized by their **product history**, not by the stability classification of individual contract formats. A published product can contain both stable and candidate surfaces.

For authoritative present-day interface maturity and consumer obligations, use the [Stability and Compatibility Contract](../reference/stability-compatibility-contract.md), [Versioning Model](../reference/versioning.md) and [Post-v1 Surface Classification](../reference/post-v1-candidate-integration-surfaces.md).

## Current release

[v1.4.0: Core Interface and Public Adapter Onboarding](v1.4.0.md) is the published Core product baseline.

It includes the exact external GitHub onboarding composition and new independently classified candidate interface and evidence contracts. Publication does not imply that every surface is stable, or prove a native adapter executed.

## Previous v1.x releases

- [v1.0.0](v1.0.0.md): origin of the stable Mission Data Contract commitment.
- [v1.1.0](v1.1.0.md): candidate Core inspection consolidation.
- [v1.2.0](v1.2.0.md): stable Mission Snapshot and coherent Core Integration Input Set boundary.
- [v1.3.0](v1.3.0.md): candidate Adapter Management foundation.

These pages preserve release-specific descriptions, not current product instructions.

## Historical v0.x releases

The v0.x notes, from [v0.2.2](v0.2.2.md) through [v0.12.0](v0.12.0.md), record the project evolution before its first stable Mission Data Contract release. They remain accessible through the Historical v0.x Releases navigation group.

Some statements in earlier release notes are intentionally tied to their historical release state. Do not use those notes as a substitute for current installation instructions or interface maturity classifications.

## Architectural decisions

The [ADR collection](../adr/ADR-0001-mission-model-first.md) records why particular engineering decisions were adopted. ADR age alone does not make a decision obsolete. The navigation groups these documents by engineering area, independently from release chronology.

## Documentation ownership

This page is a reading guide. It does not change release tags, compatibility policies, installed software, source code, artifacts or historical decisions. All existing release and ADR file paths remain unchanged.
